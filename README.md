# BookNest — Library Management System

Read • Learn • Grow

A Laravel + MySQL library management system with role-based access control
(admin/user), real search/filter/pagination, a deterministic personalized
recommendation engine, and a backend-controlled AI assistant.

## ⚠️ How this project was built — please read first

This is now a **complete Laravel 11 project skeleton** — `artisan`,
`bootstrap/app.php` + `bootstrap/providers.php`, `public/index.php`,
`.htaccess`, every default `config/*.php` file (plus the custom application layer), `storage/` with all the directories Laravel expects,
`tests/` with real (not placeholder) feature/unit tests, `routes/console.php`,
`database/factories/UserFactory.php`, and `composer.json`/`package.json`/
`vite.config.js` — laid directly on top of the full application layer
(controllers, models, policies, services, migrations, seeders, views).
You do **not** need to run `composer create-project` first; this folder
*is* the project root.

It was still written entirely by hand, in an environment with **no PHP, no
Composer, and no MySQL available**, and no network access to Packagist. So:

- Every file is real, complete code — nothing here is a stub or mockup.
- **`vendor/`, `node_modules/`, `public/build`, and `composer.lock` are not
  included** — they're always generated by `composer install` / `npm
  install`, never hand-written. `composer install` will generate a correct
  `composer.lock` on first run, same as any project that hasn't been
  installed yet.
- **None of it has actually been executed.** No `composer install`,
  `php artisan migrate`, or browser QA have been run — you're the first to
  boot it. I did do a full static consistency pass instead (routes ↔
  controllers ↔ views ↔ variables ↔ namespaces ↔ asset paths — see section
  10), which caught and fixed one real bug, but that's not a substitute for
  actually running it.

## 1. Installation

From this project's root:

```bash
composer install
cp .env.example .env
php artisan key:generate
```

That's it for installation — no manual wiring needed. The `admin`
middleware alias is already registered in `bootstrap/app.php`, and
`BookPolicy`/`CategoryPolicy`/`UserPolicy` are already registered
explicitly in `app/Providers/AppServiceProvider.php::boot()` (on top of
Laravel's `{Model}Policy` auto-discovery convention, as a belt-and-suspenders
measure).

## 2. Database

```bash
# configure DB_* in .env (MySQL) then:
php artisan migrate
php artisan db:seed
```

`db:seed` runs `UserSeeder` (1 admin + 1 demo reader with a filled-in
profile), `CategorySeeder` (10 categories), and `BookSeeder`, which seeds
**186 real books** — every one uses an actual supplied cover image, none
generated or placeholder:

- 82 titles from `books/Arabic Books/` → category "Arabic Literature"
- 72 titles from `books/English Books/` → Fantasy / Romance / Literary
  Fiction / Young Adult, hand-mapped for recognizable series (ACOTAR,
  Shatter Me, Colleen Hoover, etc.)
- 32 titles from `books/programming books/` → Programming / AI /
  Web Development / Database / Networking & Security

Author and category were curated by title for everything recognizable;
**titles I couldn't confidently identify are seeded with `author = NULL`**
("Unknown author" in the UI) rather than a guessed name — fix these from
`/admin/books` as needed. See `database/seeders/books_seed_data.json` for
the full mapping used.

### Storage link (only needed for admin-uploaded covers, not seeded ones)

```bash
php artisan storage:link
```

Seeded covers live under `public/images/covers/...` directly (no
`storage:link` needed for those); only covers uploaded later through the
admin book form go through `storage/app/public`.

## 4. Library Assistant

The Library Assistant is fully rule-based and requires **no AI API key**. It makes no external model/API calls. It uses predefined responses plus safe Eloquent queries against the existing catalog for books, authors, categories, availability, recommendations, and admin-only statistics.

The assistant can run normally with an empty `.env`; there is no `AI_API_KEY`, `AI_MODEL`, or `AI_BASE_URL` configuration.

## 5. Run it

```bash
php artisan serve
npm install && npm run build   # only needed if you add a bundler; app.css/app.js are plain files, no build step required
```

## 6. Roles & security model

- Exactly two roles: `admin`, `user`. Default on registration: `user`.
- `RegisterRequest` has no `role` rule and `RegisterController` hardcodes
  `role: 'user'` — a POST body with `role=admin` is simply ignored.
- Admins are created only via `UserSeeder` or by an existing admin editing
  a user's role in `/admin/users` (never through public registration).
- Every `/admin/*` route sits behind `['auth', 'admin']` middleware
  (`EnsureUserIsAdmin`) — hiding sidebar links is a UX nicety, not the
  actual protection.
- `BookPolicy`, `CategoryPolicy`, `UserPolicy` gate every write in the
  relevant controllers via `$this->authorize(...)`, independent of the
  middleware, so even a direct Eloquent call from a future controller
  can't skip the check.
- A user can only edit their own profile (`UserPolicy::update`); only an
  admin can change roles, and never their own (`UserPolicy::changeRole`),
  which prevents a zero-admin lockout.

## 7. Recommendation engine

`app/Services/RecommendationService.php` is fully deterministic — same
profile + same book always yields the same score, no `rand()` anywhere.
It scores each book as:

`score = 0.4 × categoryMatch + 0.6 × keywordOverlap`

- `categoryMatch` is 100 if the book's category is one of the profile's
  preferred categories, else 0.
- `keywordOverlap` tokenizes the profile's interests/skills/goals/
  preferred-category names and the book's title/category/description
  (Unicode-aware, so Arabic titles tokenize correctly too), and scores
  overlap with title hits weighted 2× over description hits.

Change a user's interests or preferred categories on `/profile` and the
homepage recommendations change accordingly — nothing is hardcoded.

## 8. Library Assistant architecture

The assistant is deterministic: it does not call OpenAI, Gemini, Anthropic, or any other external AI service. `AIChatController` authenticates the user before dispatching the request, and admin-only statistics are checked with `$user->isAdmin()` before statistics are returned. Catalog searches are performed directly with Eloquent and the assistant only formats those results into predefined responses.

## 9. Running locally with XAMPP or Laragon (MySQL)

1. **Get the project into place.**
   - XAMPP: unzip this into `C:\xampp\htdocs\booknest` (or copy `app/`,
     `database/`, `resources/`, `routes/web.php`, `public/*`, `config/*`,
     root files onto a fresh `composer create-project laravel/laravel`
     as in section 1 — see the note in section 10 about why that step
     is still required).
   - Laragon: put it under `C:\laragon\www\booknest` the same way.
2. **Start Apache + MySQL** from the XAMPP/Laragon control panel.
3. **Create the database.** Open phpMyAdmin (`http://localhost/phpmyadmin`)
   and create a database named `booknest` (utf8mb4_unicode_ci) — or run:
   ```sql
   CREATE DATABASE booknest CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
4. **Configure `.env`.** Copy `.env.example` to `.env`. For a default
   XAMPP MySQL (root, no password) or Laragon MySQL (root, no password
   or `root`/blank depending on your Laragon MySQL version), this usually
   just works out of the box:
   ```
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=booknest
   DB_USERNAME=root
   DB_PASSWORD=
   ```
5. **Install and boot:**
   ```bash
   composer install
   php artisan key:generate
   php artisan migrate --seed
   php artisan storage:link
   php artisan serve
   ```
   Visit `http://127.0.0.1:8000`. (Under XAMPP/Laragon's own Apache you
   can instead point a vhost at `/public` and skip `artisan serve`.)
6. **Log in** with `admin@booknest.test` / `password` (admin) or
   `reader@booknest.test` / `password` (user) — see section 3.
7. **Run the test suite** (uses in-memory SQLite, configured in
   `phpunit.xml`, so it never touches your MySQL data):
   ```bash
   php artisan test
   ```

## 10. Known limitations / honest gaps

- **Not run in this environment.** I hand-wrote every skeleton file
  (`artisan`, `bootstrap/`, `public/index.php`, all of `config/`,
  `storage/` placeholders, `tests/`) to match Laravel 11's actual
  structure, but this sandbox has no PHP/Composer/MySQL and Packagist
  was network-blocked, so none of `composer install`, `migrate --seed`,
  or `artisan test` have actually been executed. I did do a full static
  consistency pass instead (see below) — but "compiles in my head" isn't
  the same as "ran green," so budget time for a first real boot.
- **`composer.lock` is intentionally not included.** It's a generated
  lockfile of exact resolved versions and hashes — fabricating one by
  hand would risk silently wrong/mismatched hashes, which is worse than
  not having it. Running `composer install` against the `composer.json`
  here will generate a correct one automatically on first install; this
  is completely normal for a project that hasn't been installed yet.
- **`vendor/`, `node_modules/`, and `public/build` are not included** —
  they're always Composer/npm-generated, never hand-written or committed.
- What I *did* verify by static analysis (all passed): every `route()`
  call in every Blade view resolves to a route actually defined in
  `routes/web.php`; every controller/method pair used in routes exists;
  every `@include`/`<x-*>` component reference resolves to a real Blade
  file; every view's variables match what its controller passes via
  `compact()`; every model's `namespace` matches its folder; brace/paren
  balance and `<?php` open tags across all class files; every one of the
  186 seeded cover image paths actually exists on disk. I also **found
  and fixed one real bug** this way: `Book::coverUrl()` was double-
  prefixing `images/` on top of already-relative paths — fixed to just
  `asset($this->cover_image)`.
- ~98 of the 186 seeded books have `author = NULL` (titles I couldn't
  confidently identify) — see section 2.
- No `npm` build is required for the app to render — `public/css/app.css`
  and `public/js/app.js` are linked directly in the layout. `package.json`
  / `vite.config.js` are provided for anyone who wants to migrate to a
  Vite-managed pipeline later; `resources/css/app.css` and
  `resources/js/app.js` are placeholder entry points for that.
- Arabic book descriptions are a single generic templated sentence per
  book (no real synopsis data was supplied for those 82 titles).
